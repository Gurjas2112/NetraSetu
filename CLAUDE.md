## 2. Your environment, and what you must not pretend

You almost certainly **cannot run MATLAB** (no licence, no GPU in your environment). Therefore:

- Write MATLAB code fully and carefully, but **never claim it runs or passes**. Mark every MATLAB
  verification step `HUMAN-VERIFY` in the pull-request description.
- Everything else must run without MATLAB. The gateway has an engine switch:
  `GATEWAY_ENGINE=fake` uses a deterministic fake that returns contract-valid results;
  `GATEWAY_ENGINE=matlab` uses the real MATLAB Engine for Python. All Python, web and
  end-to-end tests run with `fake`.
- **Never fabricate results.** Do not write sensitivity, specificity, kappa, timing or accuracy
  numbers anywhere — not in code, docs, comments, README or commit messages. Validation numbers
  come only from `eval/` output produced on the human's machine.
- Do not download datasets. Do not commit any image from APTOS, IDRiD, DRIVE or Messidor-2: their
  licences forbid redistribution. Tests use **synthetic fixtures** generated by
  `scripts/make_fixtures.py` (Section 7, M1).

## 3. Non-negotiable rules

Breaking any of these fails review regardless of anything else in the pull request.

### Clinical safety
- **Three screener-facing decisions only:** `REFER`, `ROUTINE`, `RETAKE`. Never a fourth.
  A case routed to human review is shown to the screener as `REFER` (conservative); the reviewer
  may downgrade it later, and the patient link always shows the signed decision.
- The referral threshold is applied **before** confidence: `p_referable ≥ threshold` → `REFER`,
  regardless of confidence. Only grade ≤ 1 **and** high confidence → `ROUTINE`.
- A cache hit **never** reuses another patient's study. Identical pixels on a different patient
  are flagged `same_image_other_patient` and routed to a reviewer — never auto-graded.
- `RETAKE` always carries a specific, localised instruction key — never the word "ungradeable".
  After three failed attempts the outcome is "refer for dilated exam".
- `threshold.json` is written only by `eval/` code. Never hand-edit it; never hard-code a threshold.

### Security and privacy
- No secrets in the repository, ever. `.env`, `.env.tier1` and `garage.toml` are gitignored; only
  `*.example` files are committed.
- **Patients have no accounts.** Patient access is a signed, single-use, 72-hour token bound to one
  study and one phone-number hash.
- Every clinical API response sends `Cache-Control: no-store`. Clinical data never goes in
  `localStorage`, the service-worker cache, or logs. The field device's capture queue is purged
  once synced.
- Services connect to Postgres as dedicated roles (`gateway`, `worker`) created with
  `NOBYPASSRLS`, and clinical tables use `FORCE ROW LEVEL SECURITY`. Never connect a service as
  the table owner or `postgres`.
- Return `404`, not `403`, when a record exists but belongs to another facility.
- A grader action requires a TOTP-verified session; no role may both grade and administer.

### Architecture
- **All algorithms live in MATLAB.** Do not reimplement the model in PyTorch, TensorFlow or
  scikit-learn. Python is the gateway and glue only.
- MATLAB returns **JSON text**, never structs, across the engine boundary
  (`netrasetu_analyze_json`).
- MATLAB helpers live in a plain folder `matlab/nx/` on the path, named `nx_*`. **Not** a `+nx`
  package.
- Object storage is **Garage** (`dxflrs/garage:v2.3.0`) locally. **Never MinIO** — its community
  images were discontinued. Code talks to the S3 protocol via `boto3` with path-style addressing,
  never to a vendor SDK.
- Identity is **Keycloak** (OIDC) in every tier. Do not use Supabase Auth or any other identity
  system.
- No Redis or other extra services. The inference cache is a Postgres table.

### Code hygiene
- Windows scripts are **PowerShell** (`.ps1`): `#` comments, backtick continuation, `$env:` for
  variables. Never `::` comments or `^` continuations. Provide a `.sh` twin for anything CI runs.
- Prefer Python for cross-platform tooling scripts.
- No file paths containing spaces in configs, scripts or docs.
- Pin every dependency to an exact version once it installs successfully.

## 6. Contracts

Keep `docs/CONTRACT.md`, `service/schemas.py` and the MATLAB output in exact agreement. A change
to any one requires changing all three in the same pull request, plus `contractVersion`.

### 6.1 Engine result — what `netrasetu_analyze_json(imgPath, outDir)` returns

```jsonc
{
  "contractVersion": "1.0",
  "modelVer": "netrasetu_v1",            // from nx_config
  "cfgHash": "sha256:…",                  // threshold.json hash
  "decision": "REFER | ROUTINE | RETAKE",
  "reviewRequired": true,                 // true for every REFER and every uncertain case
  "quality": {
    "verdict": "accept | enhance | reject",
    "score": 0.0,                         // 0–1
    "failureMode": "none | defocus | underexposed | overexposed | partial_fov | media_opacity",
    "phash": "16-hex-chars"
  },
  "retakeGuidanceKey": "retake.underexposed.nasal",   // only when decision = RETAKE
  "grade": 2,                             // 0–4; null when RETAKE
  "posterior": [0.02, 0.07, 0.61, 0.24, 0.06],        // length 5, sums to 1 ± 1e-6
  "pReferable": 0.91,                     // = posterior[2] + posterior[3] + posterior[4]
  "laterality": "OD | OS | unknown",
  "criteria": [
    { "key": "icdr.l2.haemorrhages_multi_quadrant", "grade": 2,
      "detail": { "count": 14, "quadrants": 3 } }
  ],
  "evidence": [
    { "type": "MA | HE | EX | SE | NV_PROXY",
      "x": 1532.4, "y": 988.7,            // sub-pixel centroid, original-image pixels
      "quadrant": "ST | SN | IT | IN",
      "distanceToFoveaDD": 1.4,           // disc diameters; null if fovea not found
      "cropPath": "<outDir>/ev/03.png",   // 200×200 native-resolution crop
      "criterionKey": "icdr.l2.haemorrhages_multi_quadrant" }
  ],
  "gradcamPath": "<outDir>/gradcam.png",
  "llp": 0.84,                            // lesion localisation precision; null if unknown
  "reportPath": "<outDir>/report.pdf",
  "fhirBundle": { }                       // FHIR R4 Bundle, NRCeS profiles
}
```

### 6.2 API study — what the gateway returns to clients

The engine result with these changes: every `*Path` becomes a presigned `*Url`; it adds
`studyId`, `patientRef` (opaque), `source` (`matlab | cache`), `flag`
(`null | same_image_other_patient | repeat_screening`), `createdAt`. When `flag` is
`same_image_other_patient`, `grade`, `posterior` and `evidence` are `null` and
`reviewRequired` is `true`.

### 6.3 HTTP endpoints

| Method | Path | Role | Notes |
|---|---|---|---|
| POST | `/analyze` | screener | multipart `file`, `patientRef`, `consentId`; header `Idempotency-Key` (UUID) |
| GET | `/study/{id}` | screener (own facility) · grader | 404 across facilities |
| GET | `/review/queue` | grader | sorted by severity × closeness to threshold |
| POST | `/review/{id}` | grader (TOTP) | `decision`, `grade`, `reasonChip` |
| POST | `/consent` | screener | records purpose, notice hash, language |
| GET | `/r/{token}` | none | patient view; single use → `410` on reuse |
| GET | `/metrics` | internal | Prometheus |
| GET | `/healthz` | none | engine + DB + storage status |

### 6.4 Metric names — must match exactly (Grafana dashboards depend on them)

`netrasetu_quality_reject_total{reason}` · `netrasetu_grade_total{grade,decision}` ·
`netrasetu_analyze_seconds` (histogram) · `netrasetu_cache_requests_total{layer,result}` ·
`netrasetu_review_seconds` (histogram) · `netrasetu_override_total{reason}`

## 9. Conventions

**Python** — type hints everywhere; Pydantic v2; `ruff` + `ruff format`; no global mutable state
except the engine handle and its lock; SQL only through parameters or `psycopg.sql`, never string
formatting; every endpoint has a test.

**TypeScript** — `strict: true`; no `any`; components small and named for what users see;
user-facing strings only through i18next keys; colours only from `tokens.css` variables — never a
literal hex in a component.

**MATLAB** — one function per file; `arguments` blocks for validation; no global variables;
`persistent` only for caches (`nx_config`, `nx_model`); return plain structs, numeric arrays and
strings only (no objects, function handles or `categorical`) so `jsonencode` works.

**SQL** — every migration numbered and forward-only; clinical tables in schema `clinical`.

**Commits and PRs** — conventional commits (`feat:`, `fix:`, `test:`, `docs:`); one milestone per
PR. Use this PR description template:

```markdown
## Milestone
## What changed
## Verified by the agent      (commands run, with results)
## HUMAN-VERIFY               (exact steps for MATLAB/GPU/accounts)
## Deviations from spec       (and why — cite AGENTS.md if it overrides)
## Open questions
```

## 10. Stop and ask the human before

- Choosing or changing the referral threshold, the clinical decision rules, or the ICDR mapping.
- Anything that needs a secret, an account, a licence or a dataset download.
- Deploying anything publicly, or pointing any tier at a database that might hold real patient data.
- Adding a dependency or service not listed in Section 4.
- Any change that would put a number into the validation documents.
- Deleting or rewriting history, migrations already applied, or files under `docs/spec/`.

When something in this file is ambiguous, choose the option that is safer for the patient and
simpler to verify, implement it, and record the choice under "Open questions" in the PR.
